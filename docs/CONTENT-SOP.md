# Content publishing SOP

Every guide follows these steps. The CMS supports each one, but the discipline is editorial.

1. **Define the problem.** Exact symptom/error text, who hits it, which platforms. Record the intent in the Brief tab (internal only).
2. **Research without copying.** Read official docs, changelogs and public forum threads. For competitors, record only domain, angle, date, whether versions were tested, and what questions remain unanswered. Never copy text or screenshots, never bypass paywalls or robots rules, never mass-harvest. Treat keyword volumes as hypotheses unless they come from a paid tool you have access to.
3. **Reproduce and test.** Break a test system the same way, fix it, and capture **original** screenshots. Fill in the Tested environment with the versions you actually used.
4. **Write for the reader.** Short intro → "Quick fix" callout only if it is accurate → "Back up first" box before risky steps → fixes ordered from safe/reversible to invasive → how to verify success → alternatives and failure modes.
5. **Source it.** Link official documentation; add each source in References with its access date; mark primary sources. News needs a primary source.
6. **Disclose.** Mark affiliate links sponsored and switch on the disclosure.
7. **Self-check.** Resolve every content-check error and review the warnings. They're advisory, not a ranking score.
8. **Editor review.** Submit for review. The editor reproduces critical steps, checks claims, and approves or requests changes.
9. **Publish or schedule.** Editors publish now or schedule (the cron publishes it).
10. **Maintain.** When software changes, re-test, update `Last tested`, and tick "material update" with a reason only when the content really changed. The SEO dashboard lists stale guides.

Prioritise 6–12 excellent tested guides over volume.

### Weekly KPI review

Published articles · indexed pages (Search Console) · impressions/clicks/top queries (Search Console) · verified new backlinks · contact leads (Inbox) · affiliate referrals (partner dashboards) · CWV by device · AdSense policy centre / revenue (after approval). Only use numbers from connected sources. Never estimate.
